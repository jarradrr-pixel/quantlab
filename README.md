# QuantLab

An AI-assisted quantitative research and paper-trading system, built for
education, research, backtesting and paper trading.

> **This system does not trade real money.** It has no live-brokerage code
> path. `QUANTLAB_TRADING_MODE` accepts only `paper`; any other value is a
> start-up failure. Nothing here is investment advice.

**Status: Phase 1 of 6 complete.** The foundation — configuration, logging,
database, orchestrator state machine, authentication and the operator console
— is built and tested. Phase 3's Alpaca paper broker adapter has also landed
ahead of Phase 2 (see below) — account verification and reconciliation are
usable from `/broker`, but order submission is implemented on the adapter and
not yet reachable from anywhere, since Phase 2's risk engine doesn't exist yet
to approve an order before it reaches a broker. See [Roadmap](#roadmap).

## Quick start

The fastest path uses the SQLite fallback and needs no Docker.

```bash
git clone <your-fork> quantlab && cd quantlab
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

cp .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"   # paste into QUANTLAB_SECRET_KEY
```

Edit `.env`: set `QUANTLAB_SECRET_KEY`, set
`QUANTLAB_DATABASE_URL=sqlite+pysqlite:///./quantlab.db`, set
`QUANTLAB_SESSION_COOKIE_SECURE=false` (you will be on plain HTTP locally), and
set the two `QUANTLAB_BOOTSTRAP_OPERATOR_*` values to create your first account.

```bash
uvicorn app.main:app --reload --port 8000
```

Open <http://localhost:8000>, sign in with the bootstrap credentials, and you
should land on the overview with the kill switch showing **engaged**. That is
correct: the system boots halted.

### With PostgreSQL and Docker

```bash
cp .env.example .env      # fill in QUANTLAB_SECRET_KEY and the bootstrap operator
docker compose up --build
```

Compose runs `alembic upgrade head` before starting the app and binds only to
`127.0.0.1:8000`. The database port is not published to the host.

> Not verified in this environment: the Docker path was written but not
> executed, because no Docker daemon was available. The application itself,
> the migrations and the test suite were all run.

### Running the checks

```bash
pytest                # 92 tests
ruff check .          # lint
mypy app              # strict type checking
```

All three pass on Python 3.12.3.

### Migrations

```bash
alembic upgrade head                              # apply
alembic revision --autogenerate -m "description"  # after changing models
alembic downgrade base                            # tear down
```

Autogenerated migrations touching the `payload` column need `astext_type=sa.Text()`
rather than the bare `Text()` Alembic emits. Check any new migration before applying.

## Architecture

The controlling idea is a privilege gradient. Language models sit at the
low-privilege end and can only emit **proposals** as validated Pydantic
objects. Everything with authority over money-adjacent actions is ordinary
deterministic Python that no model can call, modify or argue with.

```
LLM agents  ──proposals──▶  Orchestrator (FSM)  ──▶  Backtest │ Acceptance │ Risk  ──▶  Broker
   ▲                              │                                                       │
   └── no credentials             └──────────────── hash-chained audit log ───────────────┘
       no DB writes
       no broker access
```

| Component | Guarantee |
|---|---|
| Orchestrator | Transition table is data; anything absent is refused. No stage can be skipped. |
| Risk engine *(Phase 2)* | Pure Python. No approved decision, no order. |
| Acceptance engine *(Phase 2)* | Deterministic verdict a model may explain but never override. |
| Audit log | Append-only, SHA-256 hash-chained, secrets redacted before storage. |
| Human approval | Only rows written by an authenticated `Operator` count. |
| Kill switch | Boots engaged. Absent flag is read as engaged. |

Full detail in [docs/architecture.md](docs/architecture.md).

### Design decisions worth knowing

**Server-rendered console, not a React SPA.** This is a single-operator
internal tool whose critical UI is a set of approval buttons. A separate
frontend adds a build step, a token-storage problem and a CORS surface to
render forms. Jinja2 with signed session cookies gives real CSRF protection and
same-origin-only by construction. The routes stay thin, so a React frontend can
be added later against a JSON API without reworking the domain layer.

**The audit log is hash-chained.** "Immutable" implemented as an ordinary table
is just a table. Each entry commits to its predecessor's digest, so editing or
deleting any row invalidates every later row, and `/audit` reports it.

**`PAUSED` records where it came from.** A pause that cannot resume to the
exact prior stage would force a restart of the pipeline, so the project row
carries `resume_state`.

**Login throttling is hand-rolled.** slowapi's decorator rebinds the endpoint
into its own module namespace, which breaks FastAPI's dependency resolution
under `from __future__ import annotations`. The replacement in
`app/rate_limit.py` is ~40 lines and directly testable. It is per-worker and
does not replace rate limiting at the reverse proxy.

## The state machine

```
RESEARCHING → KNOWLEDGE_REVIEW → KNOWLEDGE_TESTING → HYPOTHESIS_DEVELOPMENT
→ STRATEGY_SPECIFICATION → CODE_GENERATION → CODE_VALIDATION → BACKTESTING
→ RISK_REVIEW → AWAITING_HUMAN_APPROVAL → PAPER_TRADING → PERFORMANCE_REVIEW
```

Forward edges advance exactly one stage — enforced by a test that walks the
whole table. Backward edges exist for rework (a failed knowledge test returns
to `KNOWLEDGE_REVIEW`; failed validation returns to `CODE_GENERATION`). Any
active stage can move to `PAUSED` or `REJECTED`. `REJECTED` is terminal.

Entering `PAPER_TRADING` needs all of: a legal edge, a released kill switch,
and an `approved` row in `approvals` written by an authenticated operator.

## Environment variables

Every setting is prefixed `QUANTLAB_` and documented in `.env.example`.
Unknown variables are a start-up error rather than being ignored, so a typo in
a limit name fails loudly instead of silently reverting to a default.

| Variable | Default | Notes |
|---|---|---|
| `QUANTLAB_SECRET_KEY` | random per boot | Set it, or sessions die on restart. |
| `QUANTLAB_DATABASE_URL` | SQLite file | SQLite is rejected in production. |
| `QUANTLAB_TRADING_MODE` | `paper` | Only `paper` is accepted. |
| `QUANTLAB_KILL_SWITCH_ENGAGED_ON_BOOT` | `true` | Fail closed. |
| `QUANTLAB_REQUIRE_HUMAN_APPROVAL` | `true` | Only disableable in tests. |
| `QUANTLAB_ALLOWED_SYMBOLS` | `["SPY"]` | Empty list is rejected. |
| `QUANTLAB_MAX_POSITION_PERCENTAGE` | `2.0` | Cannot exceed total exposure. |
| `QUANTLAB_MAX_TOTAL_EXPOSURE_PERCENTAGE` | `10.0` | |
| `QUANTLAB_MAX_DAILY_LOSS_PERCENTAGE` | `1.0` | |
| `QUANTLAB_MAX_ORDERS_PER_DAY` | `2` | |
| `QUANTLAB_ALPACA_PAPER_BASE_URL` | Alpaca's paper endpoint | Start-up fails if it's anything else. |

Credentials belong in a local `.env` file only. Never paste them into a chat
window, a commit, or an issue.

## Security notes

Argon2id password hashing · signed HttpOnly SameSite=Lax session cookies ·
per-session CSRF tokens compared in constant time · CSP, `X-Frame-Options:
DENY`, `nosniff` on every response · CORS off unless explicitly configured ·
generic authentication failures that do not reveal whether an account exists ·
secret redaction applied at the logging layer, not at call sites · database
errors never returned to the client verbatim.

For production, grant the application's database role `INSERT` and `SELECT` on
`audit_events` and nothing else. The hash chain makes tampering *detectable*;
the grant makes it *hard*. See [docs/security.md](docs/security.md).

## Roadmap

| Phase | Contents | Status |
|---|---|---|
| 1 | Foundation: config, logging, DB, FSM, auth, console, tests | **complete** |
| 2 | Market data, MA strategy, backtest engine, risk engine, mock broker, approvals | next |
| 3 | Alpaca paper adapter, account verification, reconciliation | **partial** — adapter, verify, reconcile built; order submission implemented but unreachable until Phase 2's risk engine exists |
| 4 | Research agent, citation tracking, knowledge base | |
| 5 | Knowledge test, hypothesis generator, sandboxed codegen | |
| 6 | Performance review, experiment tracking, strategy versioning | |

Two decisions to settle before Phase 2, both of which change the engine's
shape:

1. **Historical data provider is unspecified.** Alpaca's own bars, yfinance and
   a paid vendor differ in split and dividend adjustment, which changes both
   the crossover signal and the buy-and-hold benchmark it is measured against.
2. **The default acceptance rule and the default strategy contradict each
   other.** A 20/100 daily crossover on a single symbol produces roughly 3–6
   round trips per decade, so `minimum_out_of_sample_trades: 30` can never be
   met by the reference strategy. Either the demo strategy needs a faster
   signal or a wider universe, or the threshold needs to be per-strategy with
   the reference run documented as an exception.
